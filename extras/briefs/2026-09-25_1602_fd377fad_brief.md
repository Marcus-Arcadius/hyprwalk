## The project

hypr3d is a Hyprland plugin in /home/monero/Documents/3D:
- You walk around the desktop in 3D; windows hang on a wall in a courtyard or a glTF map.
- It has a third-person VRChat-style avatar:
  - faces, gestures and emotes (dances too)
  - spring bones
  - outfit toggles, sliders and material variants
  - a radial Action Menu
- `tools/unity2hypr3d.py` is a headless-Blender converter from a VRChat .unitypackage/.zip/project/prefab to a GLB, `<out>.hypr3d.json` and `<out>.<emote>.vrma` files. It emulates Modular Avatar 1.18.7 and VRCFury.
- `README.md` documents everything; read it first. Your memory notes have the background: hypr3d-avatar-plan (phases 1-9), hypr3d-dev-environment, hypr3d-git-commits, nested-hyprland-testing, hypr3d-mirage-map.

### 1. The MA components that are only warned about (tools/unity2hypr3d.py:3705)

These are Mesh Cutter, Scale Adjuster, Merge Blend Tree, Menu Install Target, World Fixed Object, World Scale Object, Convert Constraints, Floor Adjuster and Global Collider. For each one:
- read MA 1.18.7's model class and its pass, and where the pass runs in `ma_PluginDefinition.cs`
- then convert it, make it quiet with a written reason, or keep the warning with a better reason

My expectations, which you may correct:
- **Scale Adjuster:** static. MA scales what a bone's vertices do without scaling its children; check how its pass does it. `ModularAvatar.apply()` already re-parents nodes and rewrites skins, so it can do the same.
- **Mesh Cutter:** removes the vertices its vertex filters pick, and menu items can switch it (it's reactive). At rest, drop those triangles in the GLB. For the reactive case, find how MA does it at runtime and give hypr3d an equivalent: a shape key, or a hidden part a toggle switches.
- **Merge Blend Tree:** MA merges the tree into a direct blend tree FX layer. The FX evaluator already handles direct trees, so treat it like a Merge Animator FX layer; its toggles and sliders then come out as usual.
- **Menu Install Target:** its Menu Installer's menu goes where the target sits. That changes the menu paths toggle names and groups come from (MAToggles' virtual menu).
- **Floor Adjuster:** read what it moves. If it lifts the avatar (heels), carry the offset over; the plugin puts the avatar's origin on the ground.
- **Global Collider:** probably a settings collider every spring uses.
- **World Fixed Object, World Scale Object, Convert Constraints:** probably still out.
  - Task 2's node transforms might carry World Scale Object.
  - Constraints could become `VRMC_node_constraint`, which the plugin already runs.
  - Say what you decided.

Tests: `booth.py` (the MA accessories package, tools/test/synth/booth.py:1271) and `ma_unit.py`.

### 2. VRCFury features that are still warned about

- **Scale action** (tools/unity2hypr3d.py:5027), and more generally toggles or sliders whose clips move, turn or scale objects.
  - `Clip` keeps only objects, shape keys and materials. Size sliders that scale bones are common on Booth avatars.
  - Design node transforms for toggles and slider keys end to end: a settings key, the animator, the plugin. It's the same job as phase 9's material variants.
  - That also covers FX transform curves in general.
- **Smooth Loop (Breathing) and World Drop** (same line):
  - Smooth Loop needs a looping shape-key or transform animation.
  - World Drop leaves an object where it is in the world, so the plugin would have to detach a node.
  - Convert them if it's cheap; otherwise keep the warning with the reason.
- **Gesture combos** (tools/unity2hypr3d.py:5230): a face only when the left hand makes one sign and the right another.
  - The settings file's `gestures` map each hand, and its `both` means the same face for either hand.
  - Design combos in the settings file and the animator (src/avatar.cpp:2632, 4069).
- **Full Controller layers other than FX and Action** (tools/unity2hypr3d.py:5489):
  - A Gesture layer's hand poses are humanoid finger muscles, which `HumanAxes` can now read. They could become the plugin's per-gesture finger poses; today it curls fingers procedurally. The avatar descriptor's own Gesture layer works the same way.
  - Base, Additive, Sitting, TPose and IKPose layers are probably quiet, with reasons: hypr3d walks and sits by itself.
- **Two-axis Puppets** (tools/unity2hypr3d.py:5196), and VRChat's and MA's two- and four-axis radial puppets (skipped at tools/unity2hypr3d.py:2884):
  - A 2-D control in the Action Menu: a disc where the cursor's position is x, y.
  - 2-D keys in the settings file's sliders, blended the way VRChat's 2D blend trees and VRCFury's puppet stops blend.

Tests: `booth.py` (the VRCFury gimmicks package, tools/test/synth/booth.py:1414), `vrcf_unit.py`, and harness renders.

### 3. UnlitWF gaps (tools/unity2hypr3d.py:3424 `unlitwf_alpha`, 3271 `unlitwf_double`)

- **Stencil masks.**
  - How they work: Transparent_Mask (eyes, eyebrows) writes a stencil ID. MaskOut and MaskOut_Blend (the fringe) then draw only where that ID isn't, or draw translucent there, so the eyes show through the fringe.
  - Miku NT uses this: `Eye.mat` and `HairF.mat` have `_StencilMaskID` 10. Today the fringe covers her eyes (`S1/shots/eye-crop3.png`).
  - Carry the roles in the GLB (material extras) and implement them in the renderer (stencil buffer, draw order).
- **Outlines.**
  - The plugin draws none: not UnlitWF's `_TL_*`, not lilToon's or Poiyomi's, not MToon's in VRMs.
  - Try an inverted hull in the renderer. Keep it if it looks right, and note what it costs.
- **Smaller gaps:**
  - a back-face texture (`_BK_BackTex`) that differs from `_MainTex`
  - the light clamp (`_GL_LevelMin`/`_GL_LevelMax`)
  - inverted alpha (`_AL_InvMaskVal`): bake it into the texture's alpha
- **Mask textures.**
  - An alpha mask (`_AL_MaskTex` with `_AL_Source` 1 or 2) relies on Blender's exporter packing the mask into the base texture's alpha.
  - It hasn't been tried on a real asset, or checked in an exported GLB. Add a test that exports one and reads the GLB back.
- **Byte-identical output:** new material extras change the GLBs of avatars that use them; say which cases and why.

### 5. The emote maths (tools/unity2hypr3d.py:6298 `HumanAxes`, 6474 `unity_curve`, 6508 `HumanClip`)

- **IK goals.** Humanoid clips carry LeftFootT/Q, RightFootT/Q, LeftHandT/Q and so on. Unity uses them only when a state has Foot IK on (`m_IKOnFeet`) or the layer has an IK pass.
  - Neither VRSuya Action controller turns either on, so their goal curves don't apply.
  - Handle clips where they do: two-bone IK on the VRMA's leg turns to plant the feet.
- **Weighted tangents.** Unity evaluates a weighted key (`weightedMode`, `inWeight`/`outWeight`) as a Bezier; `unity_curve` treats it as Hermite. The VRSuya clips have none, so add a unit test.
- **TDOF** (translation degrees of freedom), if clips use it.
- **Ground truth.** Nothing has been compared with Unity frame by frame.
  - Look for a reference you can use locally, and never commit it. For example, a package with the same motion both as a humanoid clip and baked to transforms.
  - If there's none, say what you could check instead. `human_unit.py` has the T pose round trip.

## Environment and rules

- **Python:** the nix python3 can't import numpy. Run numpy and bpy scripts as `blender -b --factory-startup --python-exit-code 1 -P script.py -- args` (Blender 5.2.2). `python3 tools/unity2hypr3d.py` re-runs itself inside Blender.
- **Shell (zsh):**
  - Quote words that start with `=` and quote globs.
  - `ls` is an eza alias, so use `command ls`.
  - An unquoted `$v` isn't split into words; use `${=v}` or an array.
  - The cwd resets after every command, so set path variables in each one.
- **Testing:**
  - Test offscreen only. Never open windows on my desktop, and never load the plugin into my running Hyprland.
  - Any nested or headless Hyprland needs `HYPRLAND_NO_SD_VARS=1`. Afterwards check `systemctl --user show-environment | grep WAYLAND_DISPLAY`.
