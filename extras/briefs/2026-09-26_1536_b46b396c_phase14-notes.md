Phase 14 is committed as COMMIT on 2026-09-26 (not pushed). The user's brief (like WaylandCraft, but in hypr3d) asked for games and everyday apps in the 3D world; all eight tasks are done:

- Play mode (P, `hyprctl hypr3d play`, `hypr3d:play`, Lua `play`, Windows page Play): keyboard focus + every key but Super/Ctrl+Alt combos, buttons, wheel; pointer lock → only `PROTO::relativePointer->sendRelativeMotion`; confine → `logicConstraintRegion().closestPoint`; else a pointer over the window+popups+dialogs (`playedWith()`). Camera faces the window (PLAY_FILL 0.94). Ends on Super+Esc, leaving 3D, session lock (exitNow), window gone, other window/layer surface taking the keyboard (0.5 s grace with no focus); a window going fullscreen while focused is played (byFullscreen, reset in setPlay). Hyprland won't focus a new window while the focused one has a pointer lock (its rule, in 2D too).
- Compositor side: hook `CSurfacePassElement::discard` + `presentFeedback(m_frameTime, mon)` at RENDER_POST for drawn surfaces (games paced by the 3D view; FIFO released on monitor present anyway).
- App cursor: `lockSoftwareForMonitor` on every monitor in 3D, hook `CPointerManager::renderSoftwareCursorsFor` (only frame() the cursor surface), draw `getCurrentCursorTexture()` at `hotspot()` on the panel under the pointer; hkEnsureCursor → setCursorHidden(cursor:invisible || !hook).
- Apps (src/apps.cpp): XDG desktop entries + icon themes (hyprgraphics), Q/Apps page, `hyprctl hypr3d launch|apps`, `spawnRawProc("export HYPR3D_LAUNCH=token; cmd")` (single fork: the pid is the sh); a window is the launch's by /proc ancestry (Chromium/Electron environments are unreadable), the token, SteamAppId (Steam launches only match that or class steam_app_ID), else class for 60 s. app_rules + built-ins; spots per class per map in $XDG_STATE_HOME/hypr3d/windows/. Any other window opening in 3D on the 3D monitor goes in front of you too (the share picker is tiled, not floating).
- Windows: B page, `hyprctl hypr3d window SEL focus|bring|wall|pin|unpin|bigger|smaller|size W H|play|close`, H pin (pin_size), Shift+wheel real size (floats a tiled window), X forgets, DnD via `setPointerFocus` + `input.mouse.move` emit.
- Popups: X11 OR windows as popups of their owner (`x11Owner`, own WM_TRANSIENT_FOR walk: Hyprland 0.55.2's `x11TransientFor()` returns a Wayland window), IME popups via `m_relay.popupFromSurface`; Firefox's <select> list and tooltips are subsurfaces (panels report "surfaces").
- Keys chosen: P play, Q apps (V is the view), B windows, H pin, Super+Esc stop (the brief's), Shift+wheel real size.

VM gotchas found (see also [[hypr3d-dev-environment]]):
- Portals need graphical-session.target: vm.nix's hyprland-session.target; stop the portal services at each Hyprland start (else bound to a dead display).
- The VM's Hyprland service had ambient CAP_WAKE_ALARM, so its children had it and the portal couldn't read /proc/PID/root (EACCES): AmbientCapabilities="" there. The user's own Hyprland has CapAmb 0 (not affected).
- OBS: a pipewire-screen-capture-source made through obs-websocket CreateInput never gets past CreateSession (the Response comes, OBS never calls SelectSources: made off OBS's UI thread); the test creates it, closes OBS (it saves the collection) and relaunches: the picker ("Select what to share", class "", tiled) opens then.
- xdph 1.4.1 segfaults in libwayland-client when Hyprland quits after a screencast: checks.py counts ".xdg-desktop-po" segfaults apart (PORTAL_CRASH).
- xdph's stdout is block-buffered in the journal: LD_PRELOAD libstdbuf.so + _STDBUF_O=L in its service.
- mako is .mako-wrapped (pkill -x mako misses it); Chromium's info bar changes innerHeight after load (page.html re-titles on resize; page_to() reads it each time); Electron has no context menu of its own and pinch zoom off.
- libwayland 1.23+ debug lines are "interface#id"; wev's states are on continuation lines.
