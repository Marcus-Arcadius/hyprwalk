## The project

hypr3d is a Hyprland plugin in /home/monero/Documents/3D:
- You walk around the desktop in 3D; windows hang on a wall in a courtyard or a glTF map.
- It has a third-person VRChat-style avatar: faces, gestures, emotes, spring bones, outfit toggles and a radial Action Menu.
- `tools/unity2hypr3d.py` is a headless-Blender converter from a VRChat .unitypackage/.zip/project/prefab to a GLB plus `<out>.hypr3d.json`. It already emulates Modular Avatar (MA 1.18.7) and, since 2026-09-25, VRCFury.
- `README.md` documents everything; read it first. Your memory notes have the background: hypr3d-avatar-plan, hypr3d-dev-environment, hypr3d-git-commits, nested-hyprland-testing, hypr3d-mirage-map.

Pipeline: Avatar → adopt → Analysis (MA toggles, VRCFury toggles and resting state) → humanoid → OutfitSetup → Build.import_models/compute → ModularAvatar → link_armatures (VRCFury builds after MA: NDMF's hook runs at -11000, VRCFury's at -10000) → toggles → Blender arrange/place/materials/shapes/names/export → `ma.apply()` on the GLB → Settings.

The plugin side you may need: the settings file also takes `"emotes": [{"file" or "clip", "name", "loop", "hold", "grounded"}]` (see `src/avatar.cpp` around the `settings.get("emotes")` loop; the README's settings table doesn't list it yet). Emote files are VRMA or glTF/VRM with clips (`emotesFromFile`); VRMA faces are expressions by name. cgltf already parses `KHR_materials_variants` (mappings per primitive) but the plugin doesn't use them. The avatar is only drawn in third person (`main.cpp`, `f.avatar.visible = m_thirdPerson && ...`). The Action Menu has no slider or puppet controls.

### 1. Modular Avatar's remaining components

For each one, read what MA 1.18.7 does (its model class, its pass, and where the pass runs in `ma_PluginDefinition.cs`), then either convert it or make it quiet with a written reason. My expectations, which you may correct:
- **Replace Object:** structural; the replacement takes the target's place (parent, name, sibling order) and the target goes. Do it in `ModularAvatar` in MA's order.
- **Blendshape Sync:** like VRCFury's Blend Shape Link (already done in `class VRCFury`): the synced shape keys copy the base's at rest and follow its animations. Share code with that.
- **Material Setter and Material Swap:** reactive (menu-driven) and always-on material changes. hypr3d can't switch materials yet. Design it end to end: the converter writes the alternative materials (for example as `KHR_materials_variants`, which Blender's glTF exporter can write and cgltf parses) and the settings file's toggles say which to use; the plugin switches them. That's C++ in `src/avatar.cpp` and the renderer, tested with the harness. Always-on swaps can simply be applied in the converter. The same machinery serves VRCFury's material actions (task 2).
- **Visible Head Accessory:** the plugin never draws the avatar in first person, so probably nothing to do; confirm and make it quiet.
- **Mesh Settings:** probe anchors and bounds; check whether the plugin's lighting or culling would use them; probably quiet.
- Add them to the synthetic tests (`make.py` and/or `booth.py` through `unitygen.py`) and to `ma_unit.py`.
