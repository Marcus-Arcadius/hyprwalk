## The section 17 crash (this session's task 1): fixed

**Cause: aquamarine, not hypr3d's code or Mesa.** aquamarine 0.11.0's headless backend (the version your Hyprland 0.55.2 uses) keeps a raw `this` in each output's frame callback. When a frame is late, it's queued as an idle event. If the output is removed before that event runs, the event runs on the freed output: it writes `frameScheduled` and `lastFrame` into freed memory and emits a freed signal. Upstream fixed it on 2026-05-30 and 2026-06-06 (1699271, 6ecde03), first released in aquamarine 0.12.1.

In 3D the plugin asks for every frame as soon as the last one is out. On llvmpipe every frame is late, so a queued one is nearly certain when section 16 removes H3D-2. When the freed signal happened to crash, that was full2's crash in `CBackend::dispatchIdle`. When it didn't, the two writes corrupted a heap chunk, and glibc aborted at the next burst of mallocs: `CRenderer::init` compiling LitCourt's shaders in section 17.

|---|---|

| your aquamarine rebuilt with upstream's two commits, through `LD_LIBRARY_PATH` (`/proc/PID/maps` confirmed it was loaded) | 3 of 3 passed (43/43); the control on stock crashed as before |

**Fix, in the plugin:** [src/main.cpp:1356](src/main.cpp#L1356) `holdOutput()`, called from the `monitor.removed` listener ([:637](src/main.cpp#L637)). For a removed headless output, it queues an idle event of its own through aquamarine's public `addIdleEvent`. That event holds the output until it runs, and it runs after any frame already queued, so the frame runs on a live output. It is cleared on unload ([:751](src/main.cpp#L751)). It uses only aquamarine's public API, and it's harmless on a fixed aquamarine.

## Other things found broken, and what I did

- **aquamarine 0.11.0's headless-output use after free.** It was the cause of the section 17 crash (above). Fixed upstream in 0.12.1. The plugin now works around it, and section 16 checks that. Your desktop uses DRM monitors, which don't have this queue, so it only matters for virtual (headless) outputs.
- **hyprland-dialog segfaults** in libhyprtoolkit 0.5.4 in the VM, whenever a crashed Hyprland restarts. It's not ours. `restart_after_crash()` counts it as seen.
- **A test bug in sections 11 and 17:** section 17 waited for world `!= "LitCourt"`, which is already true in LitCourtRuntimeSun. So its "back to the courtyard" notification was still showing in section 11's frames. It now waits for `"courtyard"` and dismisses it.
- **UnlitWF's flat light and level minimum:** UnlitWF's light has no N·L. Without its toon shade it's now lit the same all round, as in VRChat. Its `_GL_LevelMin` is taken from gamma to linear. Hatsune Miku NT changes by at most 31 levels in 3–6% of pixels.
- **A wrong folder in my first lip sync run:** `speech/wav` holds the raw recordings, with silence between takes, and scored 16/28. The check is meant for the looped copies in `speech/in`: 26/28. Nothing in the code was wrong.

## Fuzzing

8324 map cases and 10308 avatar cases, 7 runs each (SP/fuzz/*/summary.txt), all under ASan+UBSan on llvmpipe. The last runs are clean: map 1000 + 1000, avatar 1000 + 4000 + 2000. Every finding was fixed in the loader, not the mutator. The checks run before `cgltf_validate` ([src/gltf.cpp:728–774](src/gltf.cpp#L728)).
- a sampler's wrap and filter values loaded into enums (gltf.cpp:240)
- misaligned accessor reads in cgltf (cgltf.h:1574, 2250)
- accessors that run past a short buffer, and offsets, counts and strides that wrap around
- `cgltf_validate` reading sparse indices before checking their view
- numbers like 1e20 cast to int (render queues, stencils, mask channels, outline modes, morph binds): `gltf::fileInt` and `fileFloat` ([src/gltf.hpp:31](src/gltf.hpp#L31))
- the sky image's index out of bounds ([src/map.cpp:887](src/map.cpp#L887))
- a skin with no joints ([src/avatar.cpp:1555](src/avatar.cpp#L1555))
- clip times that are infinite, unsorted or hours long (`MAX_CLIP` 900 s, [src/avatar.cpp:25](src/avatar.cpp#L25))
- node chains 200000 deep: quadratic in `cgltf_validate`'s loop check and in the map traversal. Deeper than 1000 is refused, and the traversal carries each parent's matrix.

I didn't fuzz again this session, because the fix touched only `main.cpp`, which the harness doesn't build.
